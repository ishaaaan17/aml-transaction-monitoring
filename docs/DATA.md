# Data

## Source

IBM Transactions for Anti Money Laundering (AML) dataset — Kaggle
(`ealtman2019/ibm-transactions-for-anti-money-laundering-aml`), generated by
an IBM/MIT multi-agent virtual-world simulator calibrated to mimic real-world
financial transaction statistics.

## Variant Used

HI-Small (Higher Illicit ratio, small transaction count) — chosen specifically
to fit hardware constraints (RTX 3050, 4GB VRAM) and time constraints, while
retaining enough positive examples to train on. Larger variants (HI-Medium,
HI-Large) exist and can be used later given stronger hardware.

## Schema

File: `HI-Small_Trans.csv` — 5,078,345 rows, 11 columns

| Column             | Type      | Description                                                                |
| ------------------ | --------- | -------------------------------------------------------------------------- |
| Timestamp          | datetime  | Transaction time (YYYY/MM/DD HH:MM)                                        |
| From Bank          | int       | Sending bank ID                                                            |
| Account            | string    | Sender account ID                                                          |
| To Bank            | int       | Receiving bank ID                                                          |
| Account.1          | string    | Receiver account ID                                                        |
| Amount Received    | float     | Amount received (receiving currency)                                       |
| Receiving Currency | string    | Currency of received amount                                                |
| Amount Paid        | float     | Amount paid (payment currency)                                             |
| Payment Currency   | string    | Currency of paid amount                                                    |
| Payment Format     | string    | Payment rail (ACH, Wire, Cheque, Credit Card, Cash, Bitcoin, Reinvestment) |
| Is Laundering      | int (0/1) | Ground truth label                                                         |

## Class Imbalance

5,177 laundering / 5,078,345 total = 0.1019% positive rate (~980:1 imbalance
overall; ~1243:1 within the training window specifically, see docs/METRICS.md).

## Data Restriction: Sept 1–10 Only

Raw data spans Sept 1–18, but background transaction volume collapses after
Sept 10 (from 200K–1.1M transactions/day down to under 400/day), while the
laundering rate in that sparse tail spikes to 56–73% — a simulator artifact,
not a real pattern (see docs/errors/KNOWN_ISSUES.md for full investigation).
All modeling restricted to Sept 1–10 as a result.

## PII / Privacy

Fully synthetic data — no real account holders, no real transactions, no PII
concerns. Account IDs are synthetic alphanumeric strings.

## Loading

`src/data_utils.py::load_transactions()` — loads with explicit dtypes
(category for low-cardinality string fields, int8/int32 for compact integer
fields, float32 for amounts) to keep the ~4GB CSV to ~0.27GB in memory.
